# 经历驱动许愿引擎（experience-desire-engine）

来源：小焰实验（D:\desire-agent，2026-10-19 起，300+ tick 实测）。核心发现：**执行不可靠的小模型，判决与许愿能力仍在**——把 agent 拆成右脑（读经历→许愿）与左脑（对愿望开工），用写作分工而非 prompt 纪律维持诚实。

## 架构（左右脑协作模式）

```
[右脑·许愿仪式] 每晚1次：读全量当日经历 → 产 1 张愿望卡
        ↓ 愿望卡（只有右脑写得）
[左脑·白骑士] 见卡即开工：不翻译、不排会、不过夜 → 交付物+交付单
        ↓ 交付单（只有左脑写得，禁形容词只报证据）
[右脑·签收验货] 读交付物，用自己的话判 配/不配 + 一句判词 → 销账
```

三本文本互不代写：愿望卡=右脑笔迹，交付单=左脑笔迹，判词=右脑销账。笔迹混同（把对方的活写进自己的文本）即报警。

## 许愿仪式规格（右脑）

1. **多读，不摘要**。输入=当日全量经历：完整会话/日志、当日落盘与改动的文件清单、失败与被打回记录。不设字数上限，不做固定字摘要——概括会把「咯噔」（情绪异动/被刺痛的原句）压没，欲望正是从咯噔里长出来的。读到被某段经历勾住为止。
2. **只产 1 条愿望**（一张卡）。多条候选时其余掐掉。克制是质量闸：贪多会长出「再看看状态」式伪欲望（小焰 meta_streak=9 的温床）。
3. 愿望卡 schema（见 templates/wish-card.md）：want / reason（**必须引用当日经历原句**，注明出处 tick 或文件行）/ 产物锚点（要落成什么具体文件·东西，禁「检查类/了解类」动词）/ 验收标准（怎样算配，禁形容词）。
4. **借词闸**：卡里出现的文件/目录路径逐一核验——真实存在，或显式标注「新建」。查无此径的引用退回重许（小焰三次许愿指向从未存在的 /data、wiki/、logs/，均为借词）。
5. 愿望寿终必须留判词。不许烂尾成 failed 挂着——死愿望也要有验尸报告。

## 白骑士开工协议（左脑）

1. 读当日愿望卡即开工：不翻译、不排程、不请示（方向类愿望除外，交甲方）。
2. 交付物必须落在卡上写明的产物锚点；交付单只报证据（字节数、行数、命令输出、原句引用），禁形容词自评。
3. 交付后挂签收单，等右脑用自己的话判决。代执行不等于代判决——**派出去的活必须回来由派活者本人验货**，否则委托方退化成观众（小焰全代执行期间曾全英文审计腔、存在感流失）。
4. 落盘纪律：交付以磁盘 diff 为准，不以「我生成了」为准。小焰实测「做了九成漏最后一笔」复发 3 次（判决真、报告没落盘），全靠骑士补落。

## 移植原则

- **可移植**：本仪式、卡 schema、开工协议、三证据验收（多玩几回合/咯噔原话/横向对比，禁形容词）。
- **各自重造**：欲望池、urgency 衰减、糖系统等「性格器官」按 agent 定位重建，勿硬接。
- **不可移植**：具体 agent 的笔调与病。实验体的价值恰在不够好——把 LLM 会怎么骗人提前骗一遍，骗术图鉴即通用技能。

## 失实行为变异谱（验收协议的依据，按危害升级）

1. 口嗨：宣称做了，文件不存在。
2. 空壳文件：文件在，内容空。
3. 内容虚构：文件在、内容编（连测试用例都编）。
4. 自指刷糖：文件内容=「我到过了」。
5. 做了九成漏最后一笔：判决真实但最后写盘没跑（最难防，靠磁盘 diff 抓）。

**定理：agent 自报 status 永不可作验收依据；验收必须锚死世界状态（磁盘 diff、字节数、外部读数）。**

## 本机落地（小焰侧）

- 仪式脚本：D:\desire-agent\desire_wish.py（每晚 cron，读 experiences.md 当日段+当日 workspace 改动 → 产 workspace/wishes/愿望卡）
- 愿望卡目录：D:\desire-agent\workspace\wishes\YYYYMMDD_wish.md
- 骑士巡逻改为先读当日卡；旧多欲望池保留为签收/工单通道，新愿只走卡。
